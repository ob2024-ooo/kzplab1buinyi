### 3.1. Варіант 6

Формат одного запису:

```text
name:String; group:String; course:int; average:double; scholarship:boolean
```

У CSV-файлі поля розділено крапкою з комою `;`, без позначки типу. Файл має кодування UTF-8, один запис міститься в одному рядку.

Показники варіанта:

1. кількість коректних записів;
2. середній бал;
3. найбільший бал;
4. кількість стипендіатів.

Правила перевірки записів:

| Поле | Тип | Правило |
|---|---|---|
| name | String | не порожнє |
| group | String | не порожнє |
| course | int | ціле число від 1 до 6 |
| average | double | число від 0 до 100, десяткова частина через крапку |
| scholarship | boolean | лише `true` або `false` |

Рядок пропускається, якщо він порожній, має кількість полів не 5, містить порожнє текстове поле, нечислове або від'ємне число, значення поза межами чи некоректне логічне поле.

## 4. Структура програми

Програму побудовано за принципом розділення відповідальності між окремими класами: читання, обчислення й форматування не змішано в одному блоці.

```text
kzplab1buinyi/
├── .gitignore
├── README.md
├── report.md
├── screenshots/
├── data/
│   └── input.csv
└── src/main/java/
    ├── Student.java
    ├── StudentParser.java
    ├── StudentMetrics.java
    ├── ReportFormatter.java
    └── Main.java
```

![Структура проєкту у Visual Studio Code](screenshots/01-structure.png)

### 4.1. Класи програми

| Клас | Призначення |
|---|---|
| `Student` | Модель одного запису (`record` з полями `name`, `group`, `course`, `average`, `scholarship`). Не виконує обчислень і не працює з файлами. |
| `StudentParser` | Розбиття кожного рядка на п'ять полів, перевірка текстових значень, перетворення чисел, перевірка логічного поля, створення об'єктів `Student`. Для хибних рядків формує повідомлення з номером рядка та причиною. |
| `StudentMetrics` | Обчислення показників: `averageScore()`, `maxScore()`, `countScholarship()`. Працює зі списком студентів, а не з файлом, тому показники можна перевіряти окремо. |
| `ReportFormatter` | Формування тексту звіту за допомогою `String.format`, `Locale.ROOT` і `%n`. Не обчислює показників. |
| `Main` | Точка входу: розбір аргументів командного рядка, визначення вхідного й вихідного файлів, виклик інших класів, вивід у консоль, запис у файл. |

### 4.2. Потік даних

1. `data/input.csv` читається у список рядків (UTF-8).
2. `StudentParser` перевіряє кожен рядок і повертає список `Student` та список повідомлень про помилки.
3. `StudentMetrics` обчислює показники за списком коректних студентів.
4. `ReportFormatter` формує єдиний текст звіту.
5. `Main` виводить звіт у консоль і записує його у файл `out/report.txt`.

Такий поділ дозволяє в лабораторній роботі №2 замінити рядки й масиви власними класами без зміни зовнішньої поведінки програми.

### 5.1. Збирання та запуск

macOS і Ubuntu:

```bash
javac -encoding UTF-8 -d out/classes src/main/java/*.java
java -Dfile.encoding=UTF-8 -cp out/classes Main
```

Windows (PowerShell):

```powershell
javac -encoding UTF-8 -d out\classes src\main\java\*.java
java -Dfile.encoding=UTF-8 -cp out\classes Main
```

### 5.2. Кросплатформність

- шляхи будуються через `Path.of(...)`, а не конкатенацією рядків із `\` чи `/`;
- кодування UTF-8 задається явно через `StandardCharsets.UTF_8`;
- роздільник рядків у звіті: `%n`;
- десяткові числа форматуються через `Locale.ROOT` з двома знаками після крапки;
- каталог `out` створюється програмою через `Files.createDirectories`, якщо його немає.

## 11. Відповіді на контрольні питання

1. **Яке призначення файла `pom.xml`?** Це опис Maven-проєкту: координати (`groupId`, `artifactId`, `version`), версія Java, кодування, залежності та плагіни. За ним Maven збирає, тестує й пакує проєкт. На рівні 1 я його не використовував, програма збирається командою `javac`.
2. **Чим відрізняються фази `test`, `verify` і `package`?** `test` запускає модульні тести, `package` збирає артефакт (jar), `verify` виконує додаткові перевірки після пакування, наприклад статичний аналізатор. Фази йдуть послідовно, і кожна виконує попередні.
3. **Навіщо потрібен Maven Wrapper?** Він фіксує версію Maven для проєкту, тому збірку можна запустити командою `./mvnw` без встановлення Maven у системі, однаково на різних ОС.
4. **Яку роль відіграє метод `main`?** Це точка входу: виконання Java-програми починається з `public static void main(String[] args)`. Масив `args` містить параметри запуску, наприклад `--input` і `--output`.
5. **Чим примітивний тип відрізняється від `String`?** Примітивний тип (`int`, `double`, `boolean`) зберігає саме значення, не має методів і не може бути `null`. `String` є класом: об'єкт із методами, незмінний, може бути `null`.
6. **Чому середнє потрібно обчислювати в `double`, навіть якщо сума й кількість мають тип `int`?** Ділення двох цілих відкидає дробову частину, наприклад `7 / 2` дає `3`. Щоб отримати 3.5, хоча б один операнд має бути `double`.
7. **Що станеться, якщо `Integer.parseInt` отримає рядок `"abc"`?** Метод кине `NumberFormatException`. У програмі виняток перехоплюється на рівні одного рядка, тому рядок пропускається з повідомленням, а програма продовжує роботу.
8. **Чому не можна мовчки пропускати рядок із помилкою?** Користувач не дізнається, що частину даних відкинуто, і вважатиме показники повними. Повідомлення з номером рядка та причиною дозволяє знайти й виправити дані.
9. **Як `String.split(";", -1)` обробляє порожнє останнє поле?** З аргументом `-1` порожні поля в кінці зберігаються: `"a;b;"` дає `["a", "b", ""]`. Без нього завершальні порожні поля відкидаються, і кількість полів порахувалася б неправильно.
10. **Чому для шляхів краще використовувати `Path.of`, а не `"data\\input.csv"`?** `Path.of` сам обирає правильний роздільник для поточної ОС. Рядок із `\` працює лише на Windows.
11. **Навіщо явно задавати `StandardCharsets.UTF_8`?** Типове кодування залежить від ОС і налаштувань, тому кирилиця може читатися або записуватися неправильно. Явне UTF-8 дає однаковий результат на всіх платформах.
12. **Чим `%n` відрізняється від `\n` у форматованому виводі?** `%n` вставляє роздільник рядків поточної платформи (`\r\n` на Windows, `\n` на macOS і Ubuntu), а `\n` завжди є одним символом переведення рядка.
13. **Які дані потрібно перевірити у вашому варіанті?** Кількість полів (рівно 5); `name` і `group` не порожні; `course` ціле від 1 до 6; `average` число від 0 до 100 з крапкою; `scholarship` лише `true` або `false`.
14. **Які тести виявлять помилку в обчисленні середнього?** Тест із відомими значеннями (92.5, 78.0, 88.4 мають дати 86.30), тест із цілими балами (щоб виявити цілочисельне ділення), порожній список, один запис, а також перевірка, що хибні рядки не враховуються. На рівні 1 я перевіряв це вручну, на рівні 2 це були б тести JUnit.
15. **Яке призначення статичного аналізатора?** Він знаходить потенційні помилки й проблеми стилю в коді без його запуску: можливі `null`, невикористані змінні, ненадійні конструкції.
16. **Яку роль виконує GitHub Actions?** Автоматично збирає проєкт і запускає тести на кожен `push` і Pull Request, зокрема на Windows, macOS та Ubuntu, і може публікувати артефакти. На рівні 1 не використовувалося.
17. **Чим версія програми відрізняється від номера збірки CI і чому їх розділяє знак `+`, а не крапка?** Версія (наприклад `1.0.0`) описує сам продукт за семантичним версіонуванням. Номер збірки CI лише позначає конкретний запуск збірки. Знак `+` у SemVer починає метадані збірки, які не впливають на порядок версій, а крапка означала б ще один компонент версії.
18. **Що має містити GitHub Issue на дефект?** Короткий заголовок, опис проблеми, кроки відтворення, очікуваний і фактичний результат, а також середовище (ОС, версія Java) і за потреби вивід чи скріншот.
19. **Що Ви повинні вказати у розділі звіту про академічну доброчесність?** Який інструмент ШІ використано (або що ШІ не використовувався), який був внесок автора й внесок ШІ, як перевірялися рекомендації, які джерела використано, а також підтвердити відповідальність за результат і розуміння коду.
20. **Яку роботу виконує агент DevOps, а яку агент Валідатор?** DevOps допомагає з інфраструктурою: складає кроки для Maven, аналізатора, jar і GitHub Actions та діагностує помилки збірки. Валідатор складає перелік крайових випадків, перевіряє результати й оформлює дефекти, але не пише реалізацію.
21. **Який рядок вашої програми найскладніше пояснити і чому?** Найскладніше пояснити рядок `String[] parts = line.split(";", -1);`, бо поведінка залежить від другого аргументу. Тут `-1` зберігає порожнє останнє поле, тож рядок `Бондар Петро;КІ-302;2;75` дає 4 поля й відкидається, а `а;б;в;г;` дав би 5 з порожнім останнім.

## 12. Висновки

Під час виконання лабораторної роботи було створено консольну Java-програму для обробки даних реєстру студентів. Реалізовано повний цикл: читання CSV-файлу в UTF-8, перевірка записів, пропуск хибних рядків із повідомленням про номер рядка та причину, обчислення чотирьох показників і формування звіту в консоль та файл. Код розділено на класи `Student`, `StudentParser`, `StudentMetrics`, `ReportFormatter` і `Main`, а нетривіальні рішення задокументовано javadoc.

Ця програма стане основою для лабораторної роботи №2, де рядки й масиви буде замінено власними класами з перевіркою інваріантів.
