## 2. Мета роботи

Створити Python-пакет, який читає CSV реєстру студентів, перетворює текстові поля на типізовані значення, будує звіт за списками, словниками й множинами, записує його у файл UTF-8, має CLI, тести `pytest`, перевірку `ruff`, збирається у wheel і перевіряється в GitHub Actions.

## 3. Формат CSV

Заголовок: `full_name,group,year,average`.

| Поле | Тип після читання | Правило |
|---|---|---|
| `full_name` | `str` | не порожнє, зайві пробіли прибираються |
| `group` | `str` | не порожня |
| `year` | `int` | від 1 до 6 |
| `average` | `float` | від 0 до 100, не `NaN` |

Рядок із комою й лапками (екранує сам модуль `csv`):

```text
"Коваль, Марія ""Мері""",КІ-302,4,88.4
```

Правила порожнього входу: файл лише із заголовком дає порожній список і коректний звіт із нулями; файл без заголовка — `DataError("Порожній CSV: немає заголовка")`. Дублікати рядків не є помилкою, їх враховують як окремі записи (множина груп при цьому лишається унікальною).

## 4. Структура модулів

| Модуль | Призначення |
|---|---|
| `errors.py` | клас `DataError(ValueError)` |
| `loader.py` | `parse_row`, генератор `iter_records`, `load_records`; читає CSV, перетворює типи, додає номер рядка до помилок |
| `analysis.py` | відбір, множина груп, словник за групами, `summarize` з `*args`/`**kwargs`, `make_summary`, `stream_summary`; файли не відкриває |
| `reporting.py` | `format_report` і `write_report`; CSV не читає |
| `cli.py` | аргументи, коди завершення, межа помилок |

Код запуску міститься лише в `cli.py` під `if __name__ == "__main__":`, тож імпорт модулів нічого не виконує (є тест).

## 5. Перетворення даних

- **Список:** `load_records` повертає `list[dict]`; відбір `[r for r in records if r["average"] >= 90]` (comprehension).
- **Множина:** `{str(r["group"]) for r in records}` — унікальні групи (set comprehension).
- **Словник:** `{group: sum(1 for r in records if r["group"] == group) for group in sorted(groups)}` — кількість за групами (dict comprehension, ключі впорядковано).
- Типи полів: `year` — `int`, `average` — `float`, текст нормалізується (`" ".join(text.split())`).

## 6. Функції

`summarize(records, *metrics, minimum_average=0.0, **labels)`:

- `minimum_average=0.0` — типове значення (незмінний об'єкт, стану між викликами немає);
- `*metrics` — кортеж назв числових полів (`year`, `average`);
- `**labels` — словник підписів для метрик.

```python
summarize(
    records, "average", "year", minimum_average=90.0, average="Сума", year="Курси"
)
# {"count": 4, "Сума": 370.1, "Курси": 17.0}
```

Невідома метрика дає `ValueError`, порожній після відбору набір дає суму `0.0`. Поведінку перевіряють тести.

## 7. Алгоритм аналізу

1. Відбір: `average >= threshold` (за замовчуванням 90, межа входить).
2. Множина унікальних груп.
3. Словник кількості відмінників за групами.
4. Середній бал за всіма записами (для порожнього набору `0.0`).
5. Найкращий результат: `min` за ключем `(-average, full_name, group)`, тому за рівності балів вибір однозначний.

Звіт не залежить від порядку рядків у файлі: групи сортуються, а результат не залежить від перестановки записів (є тест).

## 8. Обробка помилок

| Ситуація | Виняток / код | Повідомлення | Причина (`from`) |
|---|---|---|---|
| Хибне число `average` | `DataError`, код 1 | `Рядок 2: поле average має бути числом` | `ValueError` |
| Хибний `year` | `DataError`, код 1 | `Рядок N: поле year має бути цілим числом` | `ValueError` |
| Значення поза межами | `DataError`, код 1 | `Рядок N: поле average має бути від 0 до 100` | немає |
| Порожнє або відсутнє значення | `DataError`, код 1 | `Рядок N: поле average порожнє` | немає |
| Забагато полів | `DataError`, код 1 | `Рядок N: забагато полів` | немає |
| Відсутній стовпець | `DataError`, код 1 | `Відсутні стовпці: average` | немає |
| Файл без заголовка | `DataError`, код 1 | `Порожній CSV: немає заголовка` | немає |
| Файла немає | `OSError`, код 3 | `Помилка файла: ...` | — |
| Помилка аргументів | `argparse`, код 2 | довідка про використання | — |
| Неочікувана помилка | код 4 | `Неочікувана помилка: ...` | — |

Голого `except` немає; `except Exception` використано лише на межі CLI, де помилка перетворюється на повідомлення й ненульовий код. `raise ... from error` зберігає першопричину, і CLI виводить її рядком `Причина:`. Номер рядка — це номер фізичного рядка, де закінчився запис (заголовок має номер 1).

## 10. Тестування

`python -m pytest`: 53 тести пройдено.

- **Коректні дані:** читання рядка, формат і текст звіту, порядок рядків, CRLF.
- **Порожній вхід:** лише заголовок, повністю порожній файл, порожній звіт.
- **Дублікати:** дублікати рядків зберігаються, множина лишається унікальною, словник їх враховує.
- **Помилки:** хибне число, хибний рік, відсутній стовпець, відсутнє значення в рядку, зайві поля, межі 0/100 та значення поза межами, `NaN`, наявність `__cause__`.
- **Текст із комою:** ПІБ з комою й лапками читається коректно.
- **Функції:** `summarize` з типовим значенням, `*args` і `**kwargs`, порожній відбір, невідома метрика.
- **Файл і CLI:** запис UTF-8 з `\n`, перезапис, коди завершення, повідомлення в `stderr`, запуск через `python -m`, збіг із еталоном `baseline/summary.txt`, відсутність побічних ефектів під час імпорту.

Тимчасові файли створюються через `tmp_path`.

**Зірочка (потокова обробка).** `iter_records` — генератор, `stream_summary` обчислює підсумок за один прохід без збереження записів, `itertools.islice` бере перші записи без читання всього файла. Порівняння `scripts/measure_memory.py` на 200 000 рядків (`tracemalloc`, Linux, Python 3.13):

| Режим | Піковий обсяг пам'яті | Час |
|---|---|---|
| Список записів (`load_records` + `make_summary`) | 71.03 МіБ | 2.46 с |
| Потоковий (`iter_records` + `stream_summary`) | 0.06 МіБ | 2.09 с |

Звіти обох режимів однакові. Обмеження: `tracemalloc` вимірює лише пам'ять, виділену Python (без буферів ОС), цифри залежать від машини й версії Python, а виграш за часом невеликий. Суми `float` у двох підходах можуть відрізнятися в останньому біті, тому порівнюються тексти звітів із двома знаками.

## 15. Відповіді на контрольні питання

1. **Яку роль виконує `pyproject.toml` у Python-проєкті?** У ньому описано назву й версію пакета, мінімальну версію Python, залежності, команду запуску та налаштування інструментів (`pytest`, `ruff`). За цим файлом проєкт відтворюється на іншій машині.
2. **Навіщо створюється віртуальне середовище?** Воно ізолює залежності проєкту від системного Python та інших проєктів. Його не додають до репозиторію, бо воно відтворюється за `pyproject.toml`.
3. **Чому CSV-файл відкривається з `newline=""`?** Щоб модуль `csv` сам обробляв роздільники рядків, зокрема перенесення рядка всередині лапок, і однаково працював на Windows, macOS та Ubuntu.
4. **Які типи повертає `csv.DictReader` без додаткового перетворення?** Усі значення — рядки (`str`); ключі беруться із заголовка. Для пропущених значень у короткому рядку стоїть `None`, а зайві поля збираються під ключем `None`.
5. **Чому `split(",")` не є коректним CSV-парсером?** Він ділить і за комами всередині лапок, не знімає екранування лапок і не розуміє перенесень рядка в полі. Модуль `csv` ці випадки обробляє.
6. **Як відрізняються список, словник і множина?** Список зберігає порядок і допускає повтори. Словник зіставляє ключ зі значенням. Множина зберігає лише унікальні значення без гарантії порядку.
7. **Коли comprehension робить код зрозумілішим, а коли краще використати цикл?** Коли це одне просте перетворення чи відбір. Якщо з'являються кілька вкладених умов, побічні ефекти або складне накопичення, цикл читабельніший.
8. **Що містять `*args` і `**kwargs` усередині функції?** `*args` — кортеж позиційних аргументів, що не мають власних параметрів. `**kwargs` — словник іменованих аргументів.
9. **Чому змінний об'єкт небезпечний як значення за замовчуванням?** Значення за замовчуванням створюється один раз під час визначення функції, тому змінний об'єкт (наприклад, список) зберігається між викликами і накопичує стан.
10. **Як `raise ... from error` зберігає першопричину?** Початковий виняток записується в атрибут `__cause__`, тому в повідомленні й трасуванні видно і зрозумілу помилку даних, і технічну причину (`ValueError`).
11. **Чому завантаження, аналіз і запис звіту розділяються на модулі?** У кожного модуля одна відповідальність. Аналіз можна тестувати без файлів, а формат звіту змінювати, не чіпаючи читання.
12. **Яку гарантію дає `with` під час роботи з файлом?** Файл буде закрито після завершення блоку, зокрема коли всередині виникла помилка.
13. **Чому звіт має формуватися в детермінованому порядку?** Щоб однакові дані завжди давали однаковий текст незалежно від порядку рядків у вході; тоді звіт можна порівнювати з еталоном у тестах.
14. **Які випадки повинні бути перевірені для порожнього CSV?** Файл лише із заголовком (коректний порожній результат із нулями), файл без заголовка (помилка) і поведінка функцій аналізу на порожньому списку.
15. **Чим тест поведінки відрізняється від перевірки внутрішньої реалізації?** Тест поведінки перевіряє результат для заданого входу (значення, текст звіту, код завершення), а не назви змінних чи кроки алгоритму, тому він не ламається під час рефакторингу.
16. **Які файли знаходить `pytest`?** Файли `test_*.py` або `*_test.py` і в них функції з назвою `test_*`.
17. **Які перевірки виконує `ruff`?** `ruff check` шукає стильові й типові помилки (невикористані імпорти, порядок імпортів, потенційні баги), а `ruff format --check` перевіряє форматування без зміни файлів.
18. **Які коди завершення має CLI для успіху та очікуваної помилки?** `0` — успіх, `1` — помилка даних, `3` — помилка файла, `2` — помилка аргументів (від `argparse`), `4` — неочікувана помилка.
19. **Чому в CI запускаються і тести, і аналізатор, і пакетування?** Тести перевіряють поведінку, аналізатор — якість і стиль коду, а пакетування — що проєкт справді збирається і встановлюється. Кожна перевірка ловить свої помилки, до того ж у CI це відбувається на трьох ОС.
20. **Які дані та результати потрібно задекларувати в REPORT?** Формат CSV, структуру модулів, правила помилок і порожнього входу, повний текст звіту, команди запуску, результати `pytest`, `ruff`, збирання wheel, CI, коди завершення та використання ШІ.
